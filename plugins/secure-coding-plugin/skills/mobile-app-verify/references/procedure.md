## 2. 검증 신청 절차 (p.17~20)

### 2.1 신청 방법 (p.18~19)
- **신청**: 온라인(전자공문)으로 신청. 전자공문 미지원 기관은 이메일(kisaappverify@kisa.or.kr) 제출 가능.
- **제출물**: 오프라인 제출 — **CD(또는 DVD) 매체 방문 제출이 원칙**, 곤란 시 등기우편.
- 제출처: 전라남도 나주시 진흥길 9 한국인터넷진흥원 전자정부보호팀 (우 58324).
- 신청서 수신처: "한국인터넷진흥원장 귀하" (p.37).
- 접수 시 **접수번호가 표기된 접수증(붙임 제3호)** 을 온라인 형태로 발급하고 검증반을 할당한다. 접수된 제출물은 내부 제출물 관리 절차에 의해 안전하게 관리 (p.43).

### 2.2 제출물 목록 (p.18)

| # | 제출물 | 비고 |
|---|---|---|
| 1 | 검증신청 공문 및 **검증신청서(붙임 제1호)** | 전자문서 온라인 제출 원칙 |
| 2 | **컴파일 가능한 앱 소스코드 일체 및 실행파일**(.apk, .ipa, .app, .cap 등) | CD/DVD 방문 제출 원칙. **iOS 앱 소스코드는 개발환경인 애플 PC에서 압축파일 제작** |

### 2.3 처리 기간 (FAQ, p.19)
- 검증 순서: **접수한 순서(접수번호)** 에 따라 수행. 수요가 많으면 대기 기간 발생.
- 검증(❸) 소요: **검증 착수 후 2주일** (기능·소스코드 양에 따라 차이).
- 보완조치 확인(❺) 소요: 검증(❸)과 동일.
- 보완 재제출 기한: **보완요청 후 4주 이내** 원칙.

### 3.1 보안명세서(붙임 제2호) 구성 (p.39~42)

**[개요]**
- 식별정보: 서비스명, 신청기관, 서비스 구분, 보안공통기반 사용 여부, 운영환경/프레임워크, 배포 예정일, 배포 앱스토어
- 서비스 소개: 서비스 대상, 주요 서비스 설명
- **주요 라이브러리 사용 현황**: 출처, URL, 기능, 위치, 사용버전/배포일, 최신 배포버전 (p.40)

**[보안속성]** (p.41)
- 처리 중요정보: 개인정보/위치정보를 **수집·저장·전송 구분**으로 보안조치(정보주체 동의, SHA-256 해시 저장, AES 암호화 전송 등)와 저장/전송 경로(소스 파일 경로) 기입. 해당사항 없으면 "해당사항 없음" 명기.
- **소스코드 난독화**: 적용(상용 난독화 솔루션, ProGuard 등) / 적용 안함
- **앱 위·변조 대응**: 적용(APK 파일 해시값 검증, 상용 위·변조 솔루션 등) / 적용 안함
- 보안메커니즘: (iOS) 암호키 저장 시 키체인 사용, (공통기반 사용 시) 전송데이터 암호화 시 공통기반 VPN 사용 등

**[구현기능]** (p.42)
- 기능동작 설명 및 사용 URL(목적 포함)
- UI에서 식별되지 않는 기능(서비스 등)
- (Android) 해당 기능의 **Activity명, 사용되는 intent-filter**
- 소스코드 미제공 상용/공개모듈의 사용목적·기능 설명

## 4. 진단 결과 보고서 구성 (붙임 제6호 결과보고서, p.48~49)

> "진단 결과 보고서"라는 별도 명칭의 양식은 없으며, 해당 역할은 **붙임 제6호 결과보고서**가 수행한다.

| 장 | 내용 |
|---|---|
| 제1장 개요 | 검증 관련 규정, 검증대상 식별정보, 신청기관명·검증기관명 |
| 제2장 검증대상 제품 구조 | 제품 구성 및 주요 기능 설명 |
| 제3장 검증결과 | 소스코드 보안약점·기능 보안취약점 검증결과 **요약**, 특이사항 |
| [부록] 보완내역 | 보완요청 목록(보완요청 항목, **처리상태** 등) |

- 취약점 미발견 시 또는 검증기준의 요구수준 충족 시 결과보고서를 **공문으로 신청기관에 통보**하고 검증을 종료한다 (p.18~19).

## 5. 보완조치·재검증·검증종료 기준

### 5.1 보완(조치) 기준 (p.18~19)
- 보완 필요 시 전문기관이 **보완요청서(붙임 제4호)** 발송.
- 신청기관 조치: 보안취약점 제거, 소스코드 수정 등 → **보완조치내역서(붙임 제5호)** 작성 + 보완 조치된 제출물(소스코드 등) 재제출.
- 기한: **보완요청 후 4주 이내 재제출 원칙**.

### 5.2 재검증(보완조치 확인) 기준 (p.17, p.19~20)
- 절차상 "최초 진단 후 보안조치 확인" 단계 존재 (p.17).
- 보완조치 확인 소요기간은 최초 검증과 **동일**(착수 후 2주) (p.19).
- 검증 완료 후 배포 시 **최종 수정사항을 확인받아** 민간 앱스토어 등에 등록·배포 (p.20).

### 5.3 검증종료(중도 종료) 기준 (p.19)
전문기관은 다음의 경우 신청기관에 **검증종료를 통보할 수 있다**:
- 보완요청 이후 **4주 경과**
- **동일한 사항으로 보완요청 2회 초과**

### 5.4 판정 기준 — 원문 미기재 사항
- **"적합/부적합" 등 등급형 판정 용어, 배점·판정 등급 체계는 원문 미기재.** 원문은 "검증기준에 명시된 요구수준 만족 여부", "취약점 미발견 시", "보완요청", "검증종료 통보"라는 표현만 사용한다 (p.18~19).
- 결과보고서 제3장도 "검증결과를 **요약하여 기술**"로만 규정하며 (p.49), 부록에 보완요청 목록의 "처리상태"를 기재한다.
- **개별 항목별 판정 기호(예: 양호/취약/해당없음), 재검증 횟수 상한(2회 초과 외)도 원문 미기재.**

## 6. 배포 및 사후 관리 (p.13, p.20, p.25)

- 대민용 앱(예: "정부24"): 국내 이동통신사 또는 제조사 등 **민간 앱스토어 1곳 이상 포함**, **행정기관등의 명의**로 신청기관이 직접 배포 (p.20). 기능 검증을 실시하는 이통사/제조사 앱스토어를 반드시 1곳 이상 포함 (p.13).
- 행정용 앱(예: "모바일 업무포털"): **지원센터가 운영하는 행정용 앱스토어**로 배포. 행정(내부망)망을 이용하여 http://www.mobile.go.kr 에 On-Line 등록 (p.20).
- 배포한 모바일 대민서비스 정보를 **범정부 정보기술아키텍처 지원시스템(범정부EA포털, https://geap.go.kr)** 에 등록 (p.20).
- 운영 중에도 **정기적으로 보안취약점을 자체 점검·조치** — 적용 범위는 모바일 앱과 서비스 제공 서버 등 (p.13). 정기 점검 시 관리지침 별표1 **20개 항목을 필수 점검항목으로 포함** (p.25).
