# LLM Wiki Skill

LLM이 마크다운 파일로 구성된 위키를 **점진적으로 구축·유지**하는 개인 지식베이스 패턴.
RAG(질의 시마다 원본에서 재검색)와 달리, **지식을 한 번 컴파일해 축적**하는 것이 핵심 차이다.

---

## 핵심 개념

| 개념 | RAG 방식 | LLM-Wiki 방식 |
|------|----------|--------------|
| 지식 합성 | 질의할 때마다 재수행 | 소스 추가 시 한 번만 수행, 위키에 영구 저장 |
| 교차 참조 | 없음 | 위키 페이지 간 링크로 이미 구성됨 |
| 모순 감지 | 없음 | LLM이 ingestion 시 기존 위키와 비교해 플래그 |
| 유지 비용 | 낮음 (검색만) | 인간이 큐레이션, LLM이 나머지 전담 |

**인간의 역할**: 소스 큐레이션, 방향 설정, 좋은 질문하기  
**LLM의 역할**: 요약, 교차참조 유지, 파일 생성·갱신, 모순 플래그

---

## 디렉터리 구조

```
wiki-root/
├── CLAUDE.md          # 스키마 파일 (LLM 행동 지침) — 가장 중요
├── raw/               # 원본 소스 (불변, LLM이 읽기만 함)
│   ├── articles/
│   ├── papers/
│   └── assets/        # 이미지 등 (로컬 다운로드 권장)
├── wiki/              # LLM이 작성·유지하는 마크다운 파일
│   ├── index.md       # 전체 카탈로그 (콘텐츠 중심, 링크+요약)
│   ├── log.md         # 시간순 작업 로그 (append-only)
│   ├── overview.md    # 도메인 전체 요약·합성
│   ├── entities/      # 인물, 조직, 제품 등
│   ├── concepts/      # 개념·주제 페이지
│   └── sources/       # 소스별 요약 페이지
└── tools/             # 선택적 CLI 도구 (검색 등)
```

## CLAUDE.md 스키마 파일 작성

CLAUDE.md(또는 AGENTS.md)는 **위키의 헌법**이다. 이 파일이 LLM의 행동을 결정한다.
도메인에 맞게 커스터마이즈해야 하며, 사용자와 LLM이 함께 발전시켜 나간다.

### 최소 필수 항목

```markdown
# Wiki Schema

## 목적
[이 위키가 무엇을 다루는지 한 줄로]

## 디렉터리 구조
[위 구조 참조, 도메인 맞게 조정]

## 페이지 포맷 규칙
- 모든 위키 페이지는 YAML frontmatter 포함: title, tags, updated, source_count
- 교차 참조는 [[페이지명]] 위키링크 문법 사용
- 각 엔티티/개념 페이지 끝에 ## Sources 섹션 필수

## Ingest 워크플로
1. 소스 읽기 → 핵심 내용 파악
2. 사용자와 주요 내용 논의
3. wiki/sources/에 요약 페이지 작성
4. wiki/entities/, wiki/concepts/ 관련 페이지 갱신 (교차참조 포함)
5. wiki/index.md 업데이트
6. wiki/log.md에 항목 추가: `## [날짜] ingest | 소스제목`

## Query 워크플로
1. wiki/index.md 읽어 관련 페이지 파악
2. 관련 페이지 읽기
3. 답변 합성 (위키 페이지 인용)
4. 가치있는 답변은 새 위키 페이지로 저장

## Lint 체크 항목
- 모순: 페이지 간 상충되는 주장
- 오래된 정보: 최신 소스가 갱신했어야 할 페이지
- 고아 페이지: 인바운드 링크 없는 페이지
- 빠진 개념: 여러 곳에서 언급되나 전용 페이지 없는 것
- 누락 교차참조

## 위키 규칙
- raw/ 소스는 절대 수정하지 않는다
- log.md는 append-only (기존 항목 삭제 금지)
- 모순 발견 시 새 정보를 따르되 기존 페이지에 ⚠️ UPDATED 표시
```

## 세 가지 핵심 오퍼레이션

### 1. Ingest (소스 추가)

사용자가 새 소스를 추가할 때:

```
"이 [논문/기사/메모]를 위키에 추가해줘"
"[파일/URL]을 ingest해줘"
```

**처리 순서**:
1. 소스 읽기 (파일이면 bash로 읽기, URL이면 web_fetch)
2. 주요 내용, 핵심 엔티티/개념, 기존 위키와의 관계 파악
3. 사용자와 간단히 논의 (선택사항 — 사용자 스타일에 맞게)
4. `wiki/sources/[소스명].md` 작성
5. 관련 entity/concept 페이지 생성 또는 갱신 (보통 5~15개 페이지)
6. `wiki/index.md` 업데이트
7. `wiki/log.md`에 항목 추가

**log.md 형식** (grep 가능하도록 일관된 prefix 유지):
```markdown
## [2026-04-18] ingest | 제목
- 요약: 무엇에 관한 소스인지 한 줄
- 갱신된 페이지: entities/A.md, concepts/B.md (신규)
- 발견한 모순: 없음 / [있으면 설명]
```

---

### 2. Query (위키 조회)

사용자가 질문할 때:

```
"X에 대해 위키에서 찾아줘"
"Y와 Z를 비교해줘"
"[주제]에 대해 내가 알고 있는 것 요약해줘"
```

**처리 순서**:
1. `wiki/index.md` 읽어 관련 페이지 식별
2. 관련 페이지들 읽기
3. 답변 합성 (출처 페이지 명시)
4. 가치있는 분석/비교는 새 위키 페이지로 저장 제안

**출력 형식은 질문에 따라 다르게**:
- 일반 질문 → 마크다운 텍스트 + 위키 출처
- 비교 → 표
- 시계열 → 타임라인
- 구조적 분석 → 새 wiki 페이지 (저장 제안)

---

### 3. Lint (위키 상태 점검)

사용자가 위키 상태를 점검할 때:

```
"위키 점검해줘", "lint해줘", "위키 상태 확인"
```

**점검 항목** (CLAUDE.md의 Lint 체크 항목 참조):
- 페이지 간 모순 → 최신 소스 우선, ⚠️ 표시
- 고아 페이지 → 연결해야 할 페이지 제안
- 중요하지만 페이지 없는 개념 → 신규 페이지 생성 제안
- 오래된 정보 → 갱신 필요 표시
- 새로 조사할 만한 질문 제안

---

## 위키 설정 가이드 (처음 만들 때)

사용자가 새 위키를 시작하려 하면:

1. **도메인 파악**: 어떤 주제/목적의 위키인지 확인
   - 개인 지식 (연구, 독서, 강의)
   - 팀/비즈니스 (회의록, 프로젝트, 경쟁분석)
   - 특정 도메인 (논문분석, 여행기획, 자기개발)

2. **디렉터리 구조 생성**: 도메인에 맞게 조정
3. **CLAUDE.md 초안 작성**: 위 템플릿 기반으로 커스터마이즈
4. **index.md, log.md 빈 파일 생성**
5. **첫 번째 소스 ingest 시연**

## 도구 권장사항

| 도구 | 용도 | 필수 여부 |
|------|------|---------|
| **Obsidian** | 위키 탐색, 그래프 뷰, 웹 클리퍼 | 권장 |
| **qmd** | 위키 검색 (100+ 페이지 시) | 선택 |
| **Marp** | 위키 내용으로 슬라이드 생성 | 선택 |
| **Dataview** | Obsidian에서 frontmatter 쿼리 | 선택 |
| **Git** | 버전 관리, 협업 | 권장 |

**Obsidian 설정 팁**:
- Attachment folder: `raw/assets/` → 이미지 로컬 저장
- "Download attachments" 단축키 설정
- Dataview 플러그인: YAML frontmatter 기반 동적 테이블

## 스케일링 고려사항

| 위키 크기 | 권장 접근법 |
|----------|-----------|
| ~50 페이지 | index.md로 충분 |
| 50~200 페이지 | index.md + 카테고리 구조화 |
| 200~500 페이지 | qmd 같은 로컬 검색 도구 추가 |
| 500+ 페이지 | 임베딩 기반 검색 고려 (pgvector 등) |

## 주의사항 및 한계

- **LLM은 레이블 없는 문서를 자동으로 관계 맺지 못한다**: 개인적 맥락(누구의 문서인지)은 인간이 명시해야 한다
- **raw/ 소스는 절대 수정하지 않는다**: 원본 무결성 유지
- **위키 내용은 LLM 생성이므로 중요 정보는 인간이 검증**: 특히 사실 관계
- **log.md는 append-only**: 히스토리를 삭제하지 않는다
- **자동 삭제 금지**: LLM이 "오래됐다"고 판단해도 파일을 삭제하지 않는다 — 사용자가 직접 결정
