> 페이지는 원문 본문 페이지. **이 문서는 원문 기재 내용만 수록한다** (현행 보정은 SKILL.md 4·5장 참조).

## 항목별 정의 요약과 핵심 코딩 규칙

### 제1절 — 입력데이터 검증 및 표현 (19개)

> 절 도입부 요지: 유효한 입력데이터만 허용하고, 부득이한 경우 입력값을 검증하여 검증된 데이터만 허용한다.

**1. SQL 삽입 (CWE-89, p.3)** — 입력 유효성 미검증 시 SQL문 삽입으로 DB 열람·조작 가능.
규칙: 인자화된 질의문 사용. 필터링 시 SQL 단어 금지·특수문자 금지·길이 제한 적용.

**2. 자원 삽입 (CWE-99, p.8)** — 외부 입력을 시스템 자원 식별자로 사용하면 임의 자원 접근·수정 가능.
규칙: 사전 정의된 적합 리스트에서 선택. 파일명이면 경로순회 문자 제거. (예제: 포트 번호를 3000~3003 범위로 제한)

**3. 크로스사이트 스크립트 (CWE-79, p.10)** — 검증되지 않은 입력이 동적 웹페이지 생성에 사용되면 접속자 권한으로 스크립트 실행.
규칙: `<` `>` `&` `"` `'` 를 `&lt;` 등으로 치환. HTML 허용 게시판은 태그 화이트리스트만 허용.

**4. 운영체제 명령어 삽입 (CWE-78, p.15)** — 외부 입력이 시스템 명령어 인수로 사용되면 임의 명령 실행.
규칙: 후보 명령어 리스트에서 선택하거나 위험 문자열 검사(`strpbrk`). (현행 보정: SKILL.md 4.5 — `system()` 금지, `execv` 사용)

**5. LDAP 삽입 (CWE-90, p.19)** — 외부 입력으로 LDAP 명령문 구성 변경 가능.
규칙: DN 특수문자는 `\`, 필터 특수문자(`=` `+` `<` `>` `#` `;` `\` 등)는 일반문자로 처리. 특수문자 제거.

**6. 디렉터리 경로 조작 (CWE-22/23/36, p.21)** — `..` 상대경로 또는 절대경로 외부 제어로 예상 밖 파일 접근.
규칙: 파일 경로 인수의 일부/전부를 외부 입력으로 조합·사용하지 않는다.

**7. 정수 오버플로우 (CWE-190, p.29)** — 범위 초과 시 작은 수·음수가 되어 루프 조건/메모리 할당·복사/보안 결정 오염.
규칙: 메모리 할당 함수의 할당량 파라미터는 unsigned로 전달. 곱셈·덧셈 전 `MAX_VALUE / 배수` 등 사전 검사. (현행 보정: SKILL.md 4.2 — `__builtin_*_overflow`/C23 `ckd_*` 우선)

**8. 보호 메커니즘을 우회할 수 있는 입력값 변조 (CWE-807, p.33)** — 쿠키·환경변수·히든필드는 조작 가능.
규칙: 세션 등 중요 정보는 서버에 저장하고 보안확인 절차도 서버에서 실행. 입력값 의존 없는 구조로 변경 검토.

**9. 스택에 할당된 버퍼 오버플로우 (CWE-121, p.40)** — 지역변수/인자 버퍼가 한계치 초과.
규칙: 경계 검사(bounds checking) 수행, `strcpy()` 등 취약 함수 미사용. 인덱스 상한(`MAX_..._LENGTH`) 검사.

**10. 힙에 할당된 버퍼 오버플로우 (CWE-122, p.44)** — `malloc` 버퍼 크기 초과 저장.
규칙: 경계 검사, `strlcpy()` 같이 위험 없는 함수 사용.

**11. LDAP 처리 (CWE-90, p.48)** — 외부 입력이 LDAP 질의문 자체(베이스 등)에 영향.
규칙: 외부 입력이 베이스 디렉터리 접근에 직접 사용되지 않도록 하고, 사용 시 접근제어 수행.

**12. 시스템 또는 구성 설정의 외부 제어 (CWE-15, p.50)** — 외부에서 시스템 설정 제어 → 서비스 중단 등.
규칙: `sethostid()` 인수로 외부 입력을 직접 사용하지 않는다.

**13. 프로세스 제어 (CWE-114, p.53)** — 비신뢰 소스/환경의 라이브러리 적재 시 악성 코드 실행.
규칙: 라이브러리 적재는 신뢰 디렉터리의 절대경로 사용. 비신뢰 라이브러리는 소스 검사 후 사용.

**14. 버퍼 시작 지점 이전에 쓰기 (CWE-124, p.57)** — 음수 인덱스·포인터 감소 연산으로 버퍼 앞에 기록.
규칙: 인덱스가 음수가 되거나 포인터 연산 결과가 버퍼 이전을 가리키지 않도록 점검 후 사용.

**15. 범위 초과해서 읽기 (CWE-125, p.59)** — 인덱스 최대값 무검증 배열 참조.
규칙: 버퍼 시작 전·끝 뒤 읽기 방지. 배열 크기(size)를 인자로 전달받아 범위 검사.

**16. 검사되지 않은 배열 인덱싱 (CWE-129, p.61)** — 외부 인자를 무검사로 배열 인덱스에 사용.
규칙: `0 <= idx < size` 검사. 루프 비교 구문은 `>` 보다 `>=` 사용.

**17. 널 종료 문제 (CWE-170, p.65)** — 널 미종단 문자열 복사 시 대량 메모리 복사·오버플로.
규칙: `read()`/`readlink()` 결과에 `strcpy`/`strcat`/`strlen` 적용 금지. `strlcpy`/`strlcat` 사용.

**18. 의도하지 않은 부호 확장 (CWE-194, p.69)** — 작은 타입→큰 타입 복사 시 음수가 큰 양수로.
규칙: 크기가 다른 변수 간 값 교환 시 타입 체크로 잘못된 부호 확장 방지 (`s > 256 || s < 0` 검사 후 명시적 캐스팅).

**19. 무부호 정수를 부호 정수로 타입 변환 오류 (CWE-196, p.73)** — 큰 양수가 음수로 변환, 배열 한계 초과 접근.
규칙: 타입체크. 음수 반환 가능 함수는 signed로 받아 `< 0` 검사 후 캐스팅.

### 제2절 — 보안기능 (17개)

> 절 도입부 요지: 인증, 접근제어, 기밀성, 암호화, 권한 관리를 다룰 때 세심한 주의가 필요하다.

**20. 부적절한 인가 (CWE-285, p.77)** — 모든 실행경로에 대한 접근제어 미검사.
규칙: 역할에 따라 정보·기능 배분(공격표면 감소), 사용자 권한별 ACL 관리.

**21. 중요한 자원에 대한 잘못된 권한허용 (CWE-732, p.82)** — 중요 자원에 의도치 않은 읽기/수정 권한.
규칙: 설정·실행파일·라이브러리는 관리자만 읽고 쓰기 가능하게. `umask(0)` 금지 → `umask(077)`.

**22. 취약한 암호화 알고리즘 사용 (CWE-327, p.84)** — base64 등 단순 인코딩, RC2/RC4/RC5/RC6/MD4/MD5/SHA1/DES.
규칙(원문): 3-DES, AES, SEED 등 사용. 검증필 암호모듈 사용. (현행 보정: 3DES는 NIST 기준 2023년 말 이후 부적합, SHA-1은 용도별 판정 — SKILL.md 2.4·4.8)

**23. 사용자 중요정보 평문 저장·전송 (CWE-311, p.87)** — 민감 데이터 평문 송수신 시 스니핑 노출.
규칙: 개인정보·금융정보·패스워드는 저장·전송 모두 암호화.

**24. 하드코드된 패스워드 (CWE-259, p.93)** — 코드 내부 패스워드로 인증/통신.
규칙: 설정파일에 암호화 저장된 패스워드 사용. 관리자 인증은 일방향 함수로 암호화 저장된 패스워드 사용.

**25. 충분하지 않은 키 길이 사용 (CWE-310, p.96)** — 짧은 키는 단시간 내 해독.
규칙: RSA 2048비트 이상, 대칭 알고리즘 128비트 이상. (정밀 판정: `crypto-policy-kr`)

**26. 적절하지 않은 난수 값의 사용 (CWE-330, p.99)** — 예측 가능한 난수로 다음 값 예상 가능.
규칙(원문): 랜덤 seed 변경 사용. 취약 패턴: seed 미사용/상수 seed/예측 가능 seed. (현행 보정: `rand()` 자체 금지 — SKILL.md 4.8)

**27. 패스워드 평문 저장 (CWE-256, p.102)** — 환경설정 파일 평문 패스워드는 접근자 전원에게 노출.
규칙: 패스워드는 암호화해서 파일로 저장.

**28. 하드코드된 암호화 키 (CWE-321, p.107)** — 하드코드 키 사용 시 암호화 정보 유출 가능성 상승.
규칙: 패스워드를 상수로 내부 저장 금지. 대칭 AES/ARIA/SEED/3DES 권고(원문), RSA 2048 이상, MD4/MD5/SHA1 금지.

**29. 주석문 안의 패스워드 등 주요정보 (CWE-615, p.111)** — 주석 내 패스워드는 역공학으로 노출.
규칙: 개발 중 주석에 남긴 패스워드·보안 관련 내용은 개발 종료 후 반드시 제거.

**30. 솔트 없이 일방향 해쉬 함수 사용 (CWE-759, p.114)** — 레인보우 테이블 전수조사로 패스워드 복원.
규칙: 패스워드+솔트를 해쉬 입력으로 사용. (현행 보정: KDF 스트레칭 필수 — `crypto-policy-kr` 3항)

**31. 하드코드된 사용자 계정 (CWE-255, p.120)** — 고정 계정명 사용 시 인증 실패 원인 파악 곤란·노출 위험.
규칙: 계정·패스워드를 하드코드하지 않고 검증과정을 거쳐 얻은 값 사용.

**32. 잘못된 권한 부여 (CWE-266, p.124)** — 특정 부분 수행 시 의도치 않게 상위 권한 보유.
규칙: 응용프로그램은 사용자의 권한만으로 수행되도록 설계 (`seteuid(0)` 후 `seteuid(getuid())` 복귀).

**33. 최소 권한 적용 위배 (CWE-272, p.128)** — 상위 권한 작업 후 원래 권한으로 미복귀.
규칙: 권한 상승 수행 완료 직후 원래 권한으로 즉시 복귀 (`chroot()` 직후 `seteuid()`).

**34. 취약한 암호화: 부적절한 RSA 패딩 (CWE-325, p.132)** — OAEP 패딩 없는 RSA 사용 위험.
규칙: `RSA_public_encrypt()` 에서 `RSA_NO_PADDING` 금지 → `RSA_PKCS1_OAEP_PADDING`.

**35. 취약한 해쉬함수: 하드코드된 솔트 (CWE-326, p.134)** — 고정 솔트는 rainbow 테이블 역계산 가능.
규칙: `crypt()` 등의 salt를 상수로 사용 금지 — 예측 어려운 난수 값을 사용할 때마다 새로 생성.

**36. 같은 포트번호로의 다중 연결 (CWE-605, p.138)** — 포트에 다수 소켓 연결 허용 시 패킷 도난·서비스 도용.
규칙: `SO_REUSEADDR` 와 `INADDR_ANY` 를 동시에 사용하지 않는다.

### 제3절 — 시간 및 상태 (3개)

**37. 경쟁 조건: TOCTOU (CWE-367, p.140)** — 검사 시점과 사용 시점 사이 자원 상태 변경 → 동기화 오류·교착상태.
규칙: 파일 이름 아닌 파일 핸들로 검사·사용. 상호배제(mutex) 사용. (현행 보정: `open`+`fstat`, `O_EXCL|O_NOFOLLOW` — SKILL.md 4.6)

**38. 제대로 제어되지 않은 재귀 (CWE-674, p.147)** — 귀납 조건 없는 재귀는 무한 루프·자원 고갈.
규칙: 모든 재귀 호출을 조건문/반복문 블럭 안에서만 수행. 호출 횟수 상한 두기.

**39. 심볼릭명 매핑 오류 (CWE-386, p.149)** — 심볼릭 참조 대상이 시간에 따라 조작 가능.
규칙: 심볼릭 링크를 통한 파일 바꿔치기를 염두에 둔 프로그래밍 (파일 이름을 유기적으로 생성).

### 제4절 — 에러 처리 (3개)

**40. 오류 메시지 통한 정보 노출 (CWE-209, p.152)** — 예외 이름·스택트레이스 출력으로 내부구조 노출.
규칙: 오류 메시지는 최소한의 정보만. 미리 정의된 오류 페이지 제공.

**41. 오류상황 대응 부재 (CWE-390, p.156)** — 오류를 확인하고도 미처리 시 충돌·의도치 않은 종료.
규칙: 오류 발생 가능 부분에 제어문으로 적절한 예외 처리 (C/C++ `if`/`switch`).

**42. 적절하지 않은 예외처리 (CWE-754, p.159)** — 함수 결과값 무검사.
규칙: 값을 반환하는 모든 함수의 결과값을 검사. 광범위한 예외처리 대신 구체적인 예외처리.

### 제5절 — 코드 오류 (9개)

**43. 널 포인터 역참조 (CWE-476, p.162)** — "널이 될 수 없다"는 가정 위반 시 crash·공격 계획에 악용.
규칙: 변경될 수 있는 모든 포인터는 사용 전 점검. 널 가능 레퍼런스는 참조 전 널 검사.

**44. 부적절한 자원 해제 (CWE-404, p.165)** — 열린 fd·힙·소켓 미반환.
규칙: 자원 할당/반환 함수를 모든 패스에서 한 쌍으로 강제 (`fork()` 실패 경로 포함).

**45. 부호→무부호 변환 오류 (CWE-195, p.169)** — 음수가 큰 양수로 (`-1` → `4,294,967,295`).
규칙: 강한 타입체크 수행.

**46. 정수를 문자로 변환 (CWE-398, p.172)** — int(4byte)→char(1byte) 값 절단.
규칙: 강한 타입체크 — 충분한 크기의 정확한 타입 사용.

**47. 스택 변수 주소 리턴 (CWE-562, p.175)** — 함수 종료 후 무효 주소 참조·덮어쓰기.
규칙: 스택 지역변수의 주소를 반환하지 않는다 (힙 할당 주소 반환).

**48. 매크로의 잘못된 사용 (CWE-730, p.178)** — 쌍 사용 규칙 위배.
규칙: `pthread_cleanup_push()` 와 `pthread_cleanup_pop()` 은 같은 레벨 스코프에서 쌍으로.

**49. 스택 주소 해제 (CWE-730, p.180)** — 스택 버퍼 `free()` 시 예상치 않은 동작.
규칙: 지역 배열은 자동 제거 — 명시적 해제 금지. `strtok()` 반환값 `free()` 금지 (기존 메모리 사용).

**50. 스레드 조기 종료 (CWE-730, p.182)** — 부모가 자식보다 먼저 종료 시 자식 자원 미회수 → 메모리 누수.
규칙: `pthread_join()` 으로 대기하거나 `pthread_detach()` 로 분리.

**51. 무한 자원 할당 (CWE-770, p.185)** — 사용자당 자원 무제한 할당.
규칙: 사용 후 반드시 해제, 자원 사이즈 제한, Pool(Thread Pool, Connection Pool) 사용.

### 제6절 — 캡슐화 (2개)

**52. 남은 디버그 코드 (CWE-489, p.188)** — 배포된 디버그 코드로 식별 우회·정보 노출.
규칙: 디버그용 `main` 프로그램과 콘솔 출력 문장을 모두 제거.

**53. 시스템 데이터 정보노출 (CWE-497, p.190)** — 시스템·관리자·DB 내부 데이터 공개 시 공격 빌미.
규칙: 예외상황 발생 시 시스템 내부 정보를 화면에 출력하지 않는다.

### 제7절 — API 오용 (5개)

**54. DNS lookup에 의존한 보안결정 (CWE-247, p.193)** — DNS 엔트리 스푸핑 가능.
규칙: 보안결정에 도메인명 기반 DNS lookup 금지. IP 주소 이용이 상대적으로 안전.

**55. 위험하다고 알려진 함수 사용 (CWE-242, p.196)** — `gets()` 는 입력 크기 무검사.
규칙: 위험 함수 사용 금지 — `gets()` → `fgets()`, `vfork()` → `fork()`.

**56. 작업 디렉터리 변경 없는 chroot Jail (CWE-243, p.198)** — 상대경로(`../../etc/passwd`)로 jail 탈출.
규칙: `chroot()` 이후 `chdir("/")` 로 작업 디렉터리를 새 루트로 변경.

**57. 오용: 문자열 관리 (CWE-251, p.202)** — 윈도우 멀티바이트 문자열 함수는 모두 오버플로 유발 가능.
규칙: `_mbsXXX()` 류 사용 금지 → `_mbscpy_s()`/`_mbscat_s()`. (현행 보정: `_s` 계열은 MSVC 외 이식성 낮음 — SKILL.md 2.1)

**58. 다중 스레드에서 getlogin() 사용 (CWE-558, p.205)** — 반환값이 다른 스레드에 의해 변경 가능.
규칙: `getlogin()` 대신 스레드 안전한 `getlogin_r()` 사용, 반환값(비0) 검사.
