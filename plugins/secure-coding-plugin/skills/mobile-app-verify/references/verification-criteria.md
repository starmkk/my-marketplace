# 검증기준 전체 목록 (소스코드 보안약점 26개 + 기능 보안취약점 25개)

> 근거: 「모바일 전자정부서비스 앱 소스코드 검증 가이드라인」(행정안전부·KISA, 2021.10).
> 페이지 표기 `(p.N)`은 원문 기준. 영문명은 통용 표기를 병기한 것이며, **원문은 개별 항목에 CWE 번호를 부여하지 않는다** — 원문은 "모바일 환경 특화" 유형에 대해 공개영역(CWE, CWE/SANS Top 25, OWASP Mobile Top 10) 기준으로 제거할 것만 요구한다 (p.24).

## 1. 소스코드 보안약점 — 7개 유형 26개 항목 (p.22~24, 별표 제1호 p.32~34)

근거: 「모바일 전자정부 서비스 관리 지침」(행정안전부예규)의 '모바일 앱 보안약점' 점검기준 26개 항목(별표 3) 및 「모바일 대민서비스 보안취약점 점검가이드」 등 (p.22).

| # | 유형 | 항목명 | 비고 |
|---|---|---|---|
| 1 | 입력데이터 검증 및 표현 | SQL 삽입 (SQL Injection) | 외부 입력값이 SQL 쿼리문 생성에 사용 (p.32) |
| 2 | 입력데이터 검증 및 표현 | 경로 조작 및 자원 삽입 (Path Traversal & Resource Injection) | 외부 입력값이 자원 접근경로·자원제어에 사용 (p.32) |
| 3 | 입력데이터 검증 및 표현 | 크로스사이트 스크립트 (Cross-Site Scripting) | 브라우저에서 악의적 스크립트 실행 (p.32) |
| 4 | 입력데이터 검증 및 표현 | 운영체제 명령어 삽입 (OS Command Injection) | 외부 입력값이 OS 명령어 생성에 사용 (p.32) |
| 5 | 입력데이터 검증 및 표현 | 오버플로우(정수형, 메모리 버퍼) (Integer/Buffer Overflow) | 경계값 초과 시 예기치 않은 동작 (p.32) |
| 6 | 보안기능 | 취약한 암호화 알고리즘 사용 (Use of Weak Cryptographic Algorithm) | 기밀성 미보장 알고리즘으로 정보 노출 (p.32) |
| 7 | 보안기능 | 중요정보 평문 저장 (Plaintext Storage of Sensitive Information) | 비밀번호·개인정보 등 미암호화 저장 (p.32~33) |
| 8 | 보안기능 | 중요정보 평문 전송 (Plaintext Transmission of Sensitive Information) | 미암호화 전송 또는 안전하지 않은 채널 (p.33) |
| 9 | 보안기능 | 하드코드된 비밀번호 (Hard-coded Password) | 유출 시 노출, 주기적 변경 곤란 (p.33) |
| 10 | 보안기능 | 충분하지 않은 키 길이 사용 (Insufficient Key Length) | 기밀성·무결성 훼손 (p.33) |
| 11 | 보안기능 | 적절하지 않은 난수값 사용 (Use of Insufficiently Random Values) | 예측 가능한 난수로 공격 가능 (p.33) |
| 12 | 보안기능 | 하드코드된 암호화 키 (Hard-coded Cryptographic Key) | 유출 시 노출, 키 변경 곤란 (p.33) |
| 13 | 보안기능 | 주석문 안에 포함된 시스템 주요정보 (Sensitive Information in Comments) | 소스 유출 시 인증정보 등 노출 (p.33) |
| 14 | 시간 및 상태 | 경쟁조건: 검사 시점과 사용 시점 (TOCTOU Race Condition) | 검사 시점 ↔ 사용 시점 불일치 (p.33) |
| 15 | 에러처리 | 오류 메시지 및 시스템 데이터 정보노출 (Information Exposure Through Error Message) | 오류 메시지·스택에 내부/디버깅 정보 공개 (p.33) |
| 16 | 에러처리 | 오류 상황 대응 부재 (Missing Error Handling) | 미처리 오류로 실행정지 등 (p.33) |
| 17 | 에러처리 | 부적절한 예외 처리 (Improper Exception Handling) | 부적절한 예외 처리로 의도치 않은 상황 (p.33) |
| 18 | 코드오류 | Null Pointer 역참조 (Null Pointer Dereference) | Null 객체 주소값 참조 (p.33~34) |
| 19 | 코드오류 | 부적절한 자원 해제 (Improper Resource Release) | 자원 누수로 새 입력 처리 불가 (p.34) |
| 20 | API 오용 | 취약한 API 사용 (Use of Risky API) | 취약하다고 알려진 함수 사용 (p.34) |
| 21 | 모바일 환경 특화 | 안드로이드 애플리케이션 컴포넌트의 부적절한 접근 허용 | 외부 앱에 의한 의도치 않은 실행. 공개영역(CWE, CWE/SANS Top 25, OWASP Mobile Top 10) 기준 (p.24, p.34) |
| 22 | 모바일 환경 특화 | 민감한 정보 전송을 위한 암시적 intent 사용 (Implicit Intent for Sensitive Communication) | 도청·악성행위 삽입 가능 (p.24, p.34) |
| 23 | 모바일 환경 특화 | 접근제어 없이 내·외부 저장소 사용 | SD카드 등 저장 중요정보 노출·수정 가능 (p.24, p.34) |
| 24 | 모바일 환경 특화 | 안드로이드 권한 검사 우회 (Android Permission Check Bypass) | 권한 없는 호출 프로그램이 앱 권한 사용 (p.24, p.34) |
| 25 | 모바일 환경 특화 | 클래스 로딩 하이재킹 (Class Loading Hijacking) | 클래스 로드 디렉토리명 변경으로 경로 제어 (p.24, p.34) |
| 26 | 모바일 환경 특화 | 소스코드 난독화 미적용 (Lack of Code Obfuscation) | 역공학에 의한 소스 유출·보안메커니즘 우회 (p.24, p.34) |

※ 유형별 개수: 입력데이터 검증 및 표현 5, 보안기능 8, 시간 및 상태 1, 에러처리 3, 코드오류 2, API 오용 1, 모바일 환경 특화 6 = **26개** (p.22~24).
※ 영문 병기는 통용 표기이며 원문 미기재. 개별 CWE 번호도 원문 미기재.

## 2. 기능 보안취약점 — FV-1 ~ FV-9, 세부 25개 항목 (p.25~28, 별표 제2호 p.35)

근거: 「모바일 전자정부 서비스 관리 지침」에 따른 정기 보안취약점 점검 의무 및 '모바일 앱 보안취약점' 점검기준 20개 항목(별표 1) 필수 포함 (p.25).

| 코드 | 항목명 | 점검 내용 |
|---|---|---|
| FV-1.1 | 임의기능 — 명세되지 않은 기능 | 명세되지 않은 기능 존재 여부. 기능설명(보안명세서, UI명 등)과 실제 앱 기능 일치 (p.25, p.35) |
| FV-1.2 | 임의기능 — 악성행위 기능 | 악성행위 기능 존재 여부(불법 녹음, 임의 데이터 전송, 임의 위치정보 수집·전송 등) (p.25, p.35) |
| FV-2.1 | 최소권한 — 관리자 권한 동작 | 관리자 권한으로 동작되는 기능(권한상승 포함) 존재 여부 **(공통)** (p.25, p.35) |
| FV-2.2 | 최소권한 — 미인가 API | 인가되지 않은 API 사용 **(공통)** (p.25, p.35) |
| FV-2.3 | 최소권한 — UID 공유 | 동일한 개인키로 서명된 다른 앱과 UID 공유 여부 **(Android)** (p.25, p.35) |
| FV-2.4 | 최소권한 — 권한 적절성 | 기능 사용 요청 권한과 기능 사용 여부 적절성 **(Android)** (p.25, p.35) |
| FV-2.5 | 최소권한 — 인텐트 권한 | 인텐트 권한의 올바른 설정 여부 **(Android)** (p.25, p.35) |
| FV-3.1 | 입력값 유효성 | 외부 입력값의 유효성(지정된 길이 초과, 악성코드 포함 등) 검증 기능 존재 여부 (p.26, p.35) |
| FV-4.1 | 중요정보 관리 — 개인정보 암호화 | 개인정보의 안전한 저장·전송 암호화 적용 여부(주민등록번호, 여권번호, 면허번호, 외국인등록번호, 금융정보 등). 근거: 개인정보 보호법 제24조③ (p.26, p.35) |
| FV-4.2 | 중요정보 관리 — 일방향 암호화 | 비밀번호 및 바이오정보에 대한 일방향 암호화 저장 여부 (p.26, p.35) |
| FV-4.3 | 중요정보 관리 — 위치정보 암호화 | 개인위치정보의 안전한 저장·전송 암호화 적용 여부. 근거: 위치정보의 관리적·기술적 보호조치 권고 제8조 (p.26, p.35) |
| FV-4.4 | 중요정보 관리 — 기타 중요정보 암호화 | 기타 중요정보의 안전한 저장·전송 암호화 적용 여부 (p.26, p.35) |
| FV-4.5 | 중요정보 관리 — 수집·활용 동의 | 개인정보 및 위치정보 수집·활용에 대한 동의 여부 (p.26, p.35) |
| FV-4.6 | 중요정보 관리 — 인증 방법 | 사용자 인증 방법의 적절성 유무. 민원인: 아이디+비밀번호, 신분증명 필요 시 공동인증서 (p.26, p.35) |
| FV-4.7 | 중요정보 관리 — 비밀번호 조합규칙 | 영문·숫자·특수문자 등 조합 9자리 이상 등 (별표 제2호 p.35). ⚠️ 본문 p.26은 "8자리 이상" — 원문 내 수치 상이 |
| FV-4.8 | 중요정보 관리 — 서버 점검 | 앱과 관련된 앱(또는 웹) 서버의 기능, 중요정보 관리기능 등 점검. 별표3에서는 "필요시 점검 수행" (p.35~36) |
| FV-5.1 | 플랫폼 보안모델 — 플랫폼 변조 | 루팅, 탈옥 등과 같은 플랫폼 변조 기능 존재 여부 (p.27, p.35) |
| FV-5.2 | 플랫폼 보안모델 — 플랫폼 보안기능 | 플랫폼에서 제공하는 보안기능 사용의 적절성 여부 (p.27, p.35) |
| FV-6.1 | 상용/공개용 모듈 — 사용 적절성 | 상용 또는 공개모듈 사용 목적 및 기능의 적절성 여부 (p.27, p.35) |
| FV-6.2 | 상용/공개용 모듈 — 안전성 확인 | 해당 모듈에 대한 개발사의 안전성 확인 방법, 결과의 적절성 여부 (p.27, p.35) |
| FV-7.1 | 공개영역 취약점 | 모바일 플랫폼(안드로이드, iOS, 윈도우모바일 등) 등에 대해 알려진(및 신규) 취약점 존재 여부 (p.28, p.35) |
| FV-8.1 | 보안공통기반 — 구현 적절성 | 모바일 공통기반 기능 구현의 적절성 여부 (p.28, p.35) |
| FV-8.2 | 보안공통기반 — 미적용 시 상응 보안 | 보안공통기반을 적용하지 않은 앱의 경우 공통기반에서 제공하는 기능(앱 위·변조 등)에 부합되도록 보안 제공 (p.28, p.35) |
| FV-9.1 | 기타 — 서비스 특화 취약점 | 신청제품의 서비스 특성에 따른 추가적인 보안취약점 존재 여부 (p.28, p.35) |
| FV-9.2 | 기타 — 난독화 도구 | 모바일 앱 개발 및 배포 시 코드 난독화 도구 사용 여부. 역공학 방어 위해 난독화 도구(또는 옵션) 적용 필요 (p.28, p.35) |

※ 대분류별 세부 개수: FV-1(2) + FV-2(5) + FV-3(1) + FV-4(8) + FV-5(2) + FV-6(2) + FV-7(1) + FV-8(2) + FV-9(2) = **25개** (p.35).

**모바일 대국민 보안공통기반**(p.16 각주): 국가기관 등이 모바일 서비스 구축 시 **사용자 인증, 앱 위·변조 방지, 문서 위변조 방지** 등 공통 보안요소를 공동 활용하도록 제공하는 모바일 공용 프레임워크.
