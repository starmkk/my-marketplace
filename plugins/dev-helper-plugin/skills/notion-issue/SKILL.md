# Notion 이슈 등록·갱신

## 대상

- 실행 호스트: !`hostname`
- 이슈 DB `collection://41be93ff-c5a8-815a-8719-000bed58e099` · 리포트 DB
  `collection://41be93ff-c5a8-818a-9215-000b32131bbe`
- 열린 이슈 뷰(완료 제외, 우선순위·생성일 순):
  `https://app.notion.com/p/41be93ffc5a881e1b51fc853999bdcfc?v=41be93ffc5a881ab8b7b000cc2fad93d`

| 속성 | 형식 — 규칙 |
|---|---|
| `제목` | title — 해결책이 아닌 증상·목표 한 줄(예 "github-commit 실행 시 토큰 과다 소비") |
| `상태` | status `백로그`·`보류`·`진행중`·`완료` — 등록은 `백로그`(요청에 "진행"이면 `진행중`) |
| `우선순위` | select `높음`·`보통`·`낮음` — 요청대로, 없으면 영향 범위(작업 차단·데이터 손실 → 높음) |
| `영역` | JSON 배열 문자열 `"[\"토큰 비용\", \"plugin\"]"` — 옵션 `토큰 비용`·`plugin`·`리포트 파이프라인`· |
| | `환경 설정`, 특정 프로젝트면 프로젝트명(예 `SoundAI.Lite`) 옵션 추가 |
| `호스트` | select `공통`·`aip1`·`aip2` — 특정 호스트에서만 생기는 문제면 그 라벨, 아니면 `공통` |
| `등록 호스트` | select — 실행 호스트 소문자(`AIP2` → `aip2`). 빈 값·`!` 잔존이면 비우고 보고 |
| `관련 리포트` | 리포트 페이지 URL 배열 — 요청이 특정 날짜·리포트를 가리킬 때만 |
| `기한` | `date:기한:start` = `YYYY-MM-DD` — 요청에 날짜가 있을 때만(KST 절대 날짜) |
| `생성일` | 자동 기록되는 등록일 — 쓰지 않는다 |

- 표가 정본이다. DB 를 미리 fetch 하지 않고, 속성·옵션 오류 때만 이슈 DB 를 fetch 해 재시도·보고한다
- ToolSearch 는 한 번에 필요한 것만 — 등록 `notion-search`·`notion-create-pages`, 갱신
  `notion-update-page`(링크 모름 → `notion-search`, 완료 → `notion-fetch`), 목록
  `notion-query-data-sources`. 여러 경로가 보이면 합집합
- 본문은 템플릿 서식(제목·목록·체크박스·백틱)만 쓰므로 Markdown spec 을 읽지 않는다. 파일명·경로·
  명령은 백틱으로 감싼다(평문 `SKILL.md` 는 자동 링크로 깨짐)
- Notion 도구가 없으면 등록하지 않고 그 사실과 이슈 초안을 보여 준다

## 등록 절차

1. **내용 정리** — 요청과 지금 대화의 근거만으로 채운다. 새 조사는 하지 않는다
2. **중복 확인** — `notion-search`(`data_source_url` = 이슈 DB, `query` = 제목 핵심어, `page_size` 5,
   `max_highlight_length` 0) 1회. 완료 이슈도 섞여 나온다. 같은 문제로 보이면 만들지 말고 링크를
   보이며 덧붙일지 묻는다(상태가 필요하면 그 이슈만 fetch). 특정 리포트를 가리키면 리포트 DB 검색
   (`query` = 날짜·호스트)을 같은 응답에서 병렬로
3. **등록** — `notion-create-pages` 1회(parent `data_source_id` = 이슈 DB, 여러 건도 한 호출). 본문:

   ```markdown
   ## 배경
   - 요청 요지와 계기(날짜 포함)

   ## 원인·근거
   - 확인된 사실과 수치(출처: 파일 경로·커밋·측정 명령). 추정은 "추정" 표시

   ## 요청 내용
   - 사용자가 원하는 결과

   ## 완료 조건
   - [ ] 확인 가능한 조건(수치·명령·화면). 요청에 없으면 "(초안)" 을 붙여 제안

   ## 참고
   - 관련 파일·커밋·문서 링크

   ## 진행 기록
   - YYYY-MM-DD — 등록
   ```

4. **보고** — 이슈 링크, 제목, 상태·우선순위·영역 한 줄. 초안 항목·"관련 리포트 미연결"·비운 등록
   호스트가 있으면 함께 알린다

## 상태·결과 갱신

작업 착수·종료 때나 사용자가 요청할 때 갱신한다(링크를 모르면 등록 2 의 검색으로 찾는다).

- 착수 → `진행중`, 중단·대기 → `보류`(사유를 진행 기록에): fetch 없이 `notion-update-page` 의
  `update_properties`(상태)와 `insert_content`(position 생략 = 끝에 추가)를 같은 응답에서 병렬로
- 완료: 먼저 fetch 해 완료 조건을 대조하고, 충족한 체크박스만 `update_content` 로 체크한다. 모두
  충족했을 때만 `완료`, 남으면 `진행중` 으로 두고 남은 조건을 보고한다
- 진행 기록은 `- YYYY-MM-DD — 한 일 · 결과` 한 줄(150자 이내), 상세는 커밋·문서 경로로
- 여러 이슈의 쓰기는 한 응답에 모아 보낸다

## 목록

- "열린 이슈"·"이슈 목록" → `notion-query-data-sources` 1회(`data` = `{"mode": "view",
  "view_url": <열린 이슈 뷰>}`). 스키마 fetch·SQL 은 쓰지 않는다
- 표: 제목 · 상태 · 우선순위 · 영역 · 등록일(`생성일`) · 등록 호스트 · 기한

## 하지 않는 것

- 요청 없이 이슈 생성 — 리포트 조치 항목·작업 중 발견한 문제도 같다(필요해 보이면 등록할지 묻는다)
- 사용자가 등록한 이슈의 제목·완료 조건 임의 변경
- 비밀 값(토큰·키·비밀번호)을 본문에 옮기기 — 위치만 적는다
