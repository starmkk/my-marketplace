# Round-Trip QA 전략

## 1. 컨셉

**합성 데이터의 라벨이 진짜 wav와 일치하는지 자동 검증**.

```
원본 텍스트 ──TTS──▶ 합성 wav ──ASR──▶ 인식 텍스트
                                          │
                                          ▼
                                  원본과 비교 (CER/WER)
                                          │
                                          ▼
                              불일치 ↑이면 데이터 폐기
```

이 컨셉은 ML 데이터 검증에서 흔히 쓰는 **Cycle Consistency Check** (CycleGAN 등)와 같은 원리.
NLP에서는 **Back-translation Consistency**라고도 한다.

## 2. 왜 필요한가

합성 데이터의 실패 모드:

### 2.1 발음 정확성 실패
- MeloTTS 한자/외래어/숫자 처리 실패: "API" → "에이피아이" 대신 "에이피이"
- 동음이의어/이형동음어 처리 차이: "들리지 않다" 발음이 미묘하게 다름

### 2.2 화자 복제로 인한 발음 손상
- OpenVoice의 tone color cloning이 발음을 흐릿하게 만듦
- 일부 화자 timbre가 sibilance(치찰음) 손상

### 2.3 Augmentation 과다
- speed 0.85 + pitch -2 + noise SNR 5dB 조합이 키워드를 거의 가림
- speed 1.2 + pitch +2가 너무 빨라서 음절 누락

이런 데이터는 **합성-쪽 라벨 노이즈**로, 학습 모델을 잘못된 방향으로 끌고 간다.
사람이 일일이 듣고 검수할 수 없는 대량 데이터에서는 자동 필터가 필수.

## 3. 학계 근거

### 3.1 Speech recognition 분야
TTS 합성으로 ASR 학습 시, 합성 품질 검증을 위한 round-trip 사용 사례:
- Hayashi et al. "Back-Translation-Style Data Augmentation for End-to-End ASR." (2019)
- Speech round-trip은 ASR/TTS 양쪽 학습 데이터 검증에 모두 활용됨

### 3.2 KWS 분야 특수성
KWS 키워드는 짧고 단순(2~3 음절~짧은 구절)이라서:
- ASR 모델 입장에서 "쉬운 인식 대상"
- 따라서 round-trip CER이 낮을수록 합성 품질이 진짜로 좋다고 신뢰 가능
- ASR이 못 맞히면 사람도 못 알아들을 가능성이 높음

### 3.3 본 스킬의 한계
- ASR이 약한 발음(외래어, 신조어)에 대해 false positive 가능
- 이는 "키워드 선정 단계에서 ASR 친화적인 단어 선택"으로 일부 회피

## 4. 임계값 정하는 법

### 4.1 검증 방법
1. 합성 데이터 100~200개 샘플링
2. 사람이 직접 들어보고 "사용 가능 / 사용 불가" 라벨링
3. 동일 샘플의 ASR CER 계산
4. ROC 곡선 그려서 적절한 임계값 결정

### 4.2 권장 시작값
| 사용처 | CER 임계값 | 비고 |
|---|---|---|
| 평가셋 / 핵심 학습 | 0.10 | 매우 깐깐 |
| 일반 학습 데이터 | 0.20 | 추천 |
| 대량 학습 (커리큘럼 초기) | 0.30 | 본 스킬 기본값 |
| 약한 필터 (속도 우선) | 0.50 | 거의 필터 없음 |

KWS 키워드는 짧아서 한두 음절 틀리면 CER이 급증한다.
키워드가 긴 구절(5~10음절)이면 더 엄격하게.

## 5. 응용 패턴

### 패턴 A: 단순 필터링 (기본)
```
synth_wav 100개 → ASR → CER 계산 → CER<0.30인 것만 사용
```
가장 단순하고 효과적. 본 스킬의 기본 사용법.

### 패턴 B: 화자별 품질 분석
QA 보고서에서 speaker_id별 평균 CER를 집계해, 평균 CER이 높은 화자는
풀에서 제외. 즉 voice cloning 품질이 나쁜 화자를 자동 발견.

### 패턴 C: Augmentation 강도 튜닝
augment_config.yaml의 noise_prob, snr_db_range를 변경하며
QA 평균 CER 변화를 모니터링. CER이 갑자기 올라가는 augmentation 강도가
실배포에서도 모델이 깨지는 지점.

### 패턴 D: 키워드 자체 평가
키워드별 평균 CER이 너무 높으면 → 그 키워드는 합성-기반 학습이 어려움.
키워드 변경 또는 진짜 녹음 데이터 보강 신호.

### 패턴 E: 두 단계 필터 (엄격)
1. CER < 0.30으로 1차 필터 (대량 통과)
2. 통과한 데이터 중 무작위 5% 사람 검수
3. 사람 검수 합격률이 낮으면 임계값을 0.20으로 재필터

## 6. 흔한 실패 사례

### 6.1 ASR 모델 자체 약점에 의한 false negative
- "오케이 케이티"는 잘 인식하지만 "오케이 빅스비"는 ASR이 약함
- → 일부 키워드만 통과율이 비정상적으로 낮음
- 해결: 키워드별 CER 분포 확인 후, 특정 키워드는 임계값을 따로 둠

### 6.2 노이즈 강한 augmentation에서 일괄 폐기
- noise_prob=0.7, SNR 0~10dB가 합쳐지면 사람도 못 알아들을 수 있음
- → CER이 0.5 이상으로 폭증, 거의 다 폐기
- 해결: augment_config.yaml의 SNR 하한을 5dB 이상으로 유지

### 6.3 Round-trip이 학습 데이터를 너무 깨끗하게 만듦
- 너무 엄격한 필터(CER<0.10) → 학습 데이터에 어려운 케이스가 사라짐
- → 모델이 잡음/억양 변화에 약해짐
- 해결: 평가셋만 깐깐하게 검증, 학습셋은 다소 관대한 임계값

### 6.4 텍스트 정규화 차이로 인한 가짜 CER
- 원본 "오케이 케이티" vs ASR "오케이 케이티." (구두점)
- 본 스킬의 `normalize_korean()`이 구두점/공백/zero-width 제거로 처리
- 그래도 한자/숫자/외래어 정규화는 부족할 수 있음 — 필요시 추가 정규화

## 7. 본 스킬을 넘어선 확장

### 7.1 Whisper로 cross-check
Gemma 4 외에 OpenAI Whisper(large-v3)로도 transcribe해서 두 ASR 결과를 모두 사용.
두 모델이 모두 통과하는 데이터만 사용 → 더 robust 필터.

### 7.2 Phoneme-level 비교
글자(CER) 대신 음소(phoneme) 시퀀스로 비교. 한국어는 자모 분해해서 PER(Phoneme Error Rate).
받침/이중모음 처리에 더 정확하지만 구현 복잡.

### 7.3 KWS 모델 자체로 self-validation
1차 학습한 KWS 모델을 자기 학습 데이터에 적용해서 confidence 낮은 샘플 폐기.
self-cleaning 패턴. 본 스킬과 결합 가능.

이런 확장은 별도 스킬로 분리 가능. 본 스킬은 가장 단순하고 효과 큰 round-trip만.
