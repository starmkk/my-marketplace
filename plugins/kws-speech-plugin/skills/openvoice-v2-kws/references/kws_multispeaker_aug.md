# Multi-speaker KWS 학습 베스트 프랙티스

## 1. 학계 근거 정리

### 1.1 Synth4KWS (Google, 2024) — arXiv:2407.16840
- 50k 실데이터 baseline 대비 **EER 30.1%, AUC 46.7% 개선**
- Multi-speaker TTS 합성 데이터를 적정량 추가했을 때

### 1.2 Jia et al. 2020 — arXiv:2011.01460
- Confusion words 시나리오에서 multi-speaker TTS가 결정적
- "Augmenting the training set with the synthetic data generated by the multi-speaker TTS, we achieve significant improvement"

### 1.3 LLM-Synth4KWS (2025) — arXiv:2505.22995
- LLM으로 confusable keyword 자동 생성 + multi-speaker TTS로 합성
- 화자 다양성이 일반화 성능의 핵심 변수

### 1.4 Adversarial training for TTS-KWS (2024) — arXiv:2408.10463
- 합성-실 도메인 갭을 adversarial training으로 메움
- TTS 합성 데이터의 한계를 인정하면서도 활용 가치를 입증

## 2. 본 스킬의 권장 학습 전략

### 2.1 데이터 비율
| 실데이터 보유 | 합성 (multispk):실 비율 | 비고 |
|---|---|---|
| 10시간+ | 1:1 ~ 1:2 | 합성은 보조 |
| 1~10시간 | 2:1 ~ 3:1 | 합성을 주력으로 |
| 1시간 미만 | 5:1+ | 그래도 실데이터 필수 |
| 0시간 (cold start) | 합성만 | PoC만, 실배포 X |

### 2.2 학습 단계별 데이터 사용
1. **Pre-training**: 합성 데이터만 (대량, 다양화) → 키워드 인식 능력 학습
2. **Fine-tuning**: 실데이터 위주 (적지만 진짜) → 도메인 갭 좁히기
3. **Calibration**: 실데이터 검증셋으로 임계값 튜닝

### 2.3 평가는 **반드시** 실데이터로
합성-only 평가는 실성능을 과대평가한다. 검증/테스트셋은 실데이터 100%.

## 3. 도메인 갭 최소화 4가지 전략

### 전략 1: Acoustic augmentation (가장 효과적)
합성 데이터에 noise/RIR을 입혀서 실환경 흉내:
```bash
python ../melotts-kws/scripts/augment_audio.py \
  --in_dir ./synth_multispk \
  --out_dir ./synth_multispk_aug \
  --config augment_config.yaml
```

`augment_config.yaml`에서:
- `noise_dir`: MUSAN 등 잡음 풀
- `rir_dir`: RIRS_NOISES 등 방 임펄스 응답
- `noise_prob: 0.7` (강하게 적용)
- `rir_prob: 0.5`

### 전략 2: 실데이터와 mix 학습
wekws 학습 시 두 manifest를 합쳐 사용:
```bash
cat data/train.list data/synth_multispk_aug.list > data/train_mixed.list
```

### 전략 3: SpecAugment (wekws 자체 기능)
wekws의 학습 config에서 `spec_aug: true` 유지. 합성 데이터에도 적용된다.

### 전략 4: Curriculum learning (선택적, 효과 큼)
1) 1~5 epoch: 합성만
2) 6~10 epoch: 합성:실 = 3:1
3) 11~ epoch: 합성:실 = 1:1
4) 마지막 epoch: 실 only

## 4. False alarm rate 관리

KWS의 핵심 KPI는 **FAR (false alarm rate)**다. 즉 키워드가 아닌 말에 잘못 트리거하지 않는 능력.

합성 multi-speaker 데이터로 positive(키워드)는 다양해졌지만,
**negative(non-keyword)도 비슷한 정성으로 다양화해야 한다**.

권장:
- Positive : negative ≈ 1 : 5 ~ 1 : 10
- Negative는 **실제 한국어 일반 발화** (KsponSpeech, Zeroth-Korean 등)에서 가져옴
- 합성 negative는 가능하면 사용하지 않음 (도메인 갭이 합성 방향으로 학습됨)

## 5. 화자 풀 크기 vs 키워드당 변형 수

같은 학습 시간이라면, **화자 풀 ↑ + 키워드당 변형 ↓**가 더 좋다.

- ❌ 키워드 5개 × 화자 5명 × augmentation 50개 = 1250개 (화자 다양성 ↓)
- ✅ 키워드 5개 × 화자 50명 × augmentation 5개 = 1250개 (화자 다양성 ↑)

같은 데이터 양이라도 후자가 일반화 성능이 좋다 (Synth4KWS 결론).

## 6. 합성 품질 자동 검증 (선택)

KyungGi님이 가지고 있는 Gemma 4 E2B-it (ASR 가능)로 round-trip QA:
1. 합성한 wav 파일을 Gemma 4로 transcribe
2. 원본 텍스트와 비교 (CER/WER 계산)
3. CER > 임계값이면 해당 합성 결과 폐기

이렇게 하면 화자 풀에서 timbre cloning이 망가져 발음이 무너지는 케이스를 자동 필터링할 수 있다.

이 단계는 별도 스킬(`gemma4-asr-qa`)로 분리하면 깔끔. 본 스킬 범위는 아니지만 권장 후속 작업.

## 7. 흔한 실패 사례

1. **합성:실 비율이 너무 높음** → 학습 손실은 좋지만 실데이터 평가 폭락
2. **화자 풀 다양성 부족** (10명 미만) → 새 화자에서 인식률 ↓
3. **noise/RIR 없음** → 조용한 환경에선 잘 되지만 실배포 환경에서 폭망
4. **Negative 부재** → FAR 폭발
5. **키워드별 화자 불균형** → 일부 화자만 인식 잘 되는 편향
