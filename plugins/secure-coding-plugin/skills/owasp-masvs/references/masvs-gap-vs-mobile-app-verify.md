## 1. 비교 대상

- **국내 측 51항목** = 소스코드 보안약점 7유형 **26개**(p.22~24) + 기능 보안취약점 **FV-1~FV-9 세부 25개**(p.25~28, p.35).
- **OWASP 측 24컨트롤** = MASVS v2.1.0 8카테고리. "OWASP 에만 있는 MASWE" 열은 국내 51항목으로 지적할 수 없는 약점의 대표 ID 다(`MASWE-` 접두사 생략).
- 겹침 등급: **높음**(국내 기준으로 실질 동등 점검 가능) / **중간**(부분 겹침 — 국내 기준은 일부 측면만 규정) / **낮음**(주변부만 접촉) / **없음**(국내 대응 항목 부재).

## 3. 역방향 개요 — 국내 51항목 → MASVS

역방향(국내 항목이 MASVS 어디에 닿는가) 개요다. 국내 보고서를 MASVS 관점으로 재검토할 때 사용한다.

### 3.1 소스코드 보안약점 7유형 (26개)

| 국내 항목군 (항목 수) | 주 대응 MASVS 컨트롤 | 비고 |
|---|---|---|
| 1. 입력데이터 검증 및 표현 (5) | MASVS-CODE-4 | SQL 삽입·경로 조작·XSS·OS 명령어 삽입·오버플로우 — 기준·오탐은 `secure-coding-kr` |
| 2. 보안기능 (8) | MASVS-STORAGE-1 · CRYPTO-1 · CRYPTO-2 | 암호 알고리즘·평문 저장/전송·하드코드 키·난수 |
| 3. 시간 및 상태 (1) | 직접 대응 없음 | 경쟁조건(TOCTOU)은 MASVS 컨트롤 단위 대응이 없음 — 일반 코드 보안 영역 |
| 4. 에러처리 (3) | MASVS-STORAGE-2 (정보노출 측면) | 오류 메시지 정보노출만 부분 대응 |
| 5. 코드오류 (2) | 직접 대응 없음 | Null 역참조·자원 미해제 — MASVS 범위 밖 |
| 6. API 오용 (1) | MASVS-CODE-3 | 취약한 API 사용 ↔ MASWE-0046·0047 취지 근접 |
| 7. 모바일 환경 특화 (6) | MASVS-PLATFORM-1 · RESILIENCE-3 | 컴포넌트 접근·암시적 intent·권한 우회·클래스 로딩·난독화 |

### 3.2 기능 보안취약점 FV-1~9 (25개)

| FV 코드 | 대분류 | 주 대응 MASVS 컨트롤 | 비고 |
|---|---|---|---|
| FV-1 | 임의기능 | 직접 대응 없음 | 보안명세서-기능 일치 검증은 국내 제도 고유 절차 |
| FV-2 | 최소권한 | MASVS-PRIVACY-1 · PLATFORM-1 | FV-2.4(과도한 권한) ↔ MASWE-0066 취지 근접 |
| FV-3 | 입력값 유효성 | MASVS-CODE-4 | |
| FV-4 | 중요정보 관리 | MASVS-STORAGE-1 · NETWORK-1 · AUTH-1 · PRIVACY-4 | FV-4.2 는 AUTH-2 의 저장 측면만 접촉 |
| FV-5 | 플랫폼 보안모델 | MASVS-RESILIENCE-1 — **방향 반대** (§5) | 등치 금지 |
| FV-6 | 상용/공개용 모듈 | MASVS-CODE-3 | |
| FV-7 | 공개영역 취약점 | MASVS-CODE-3 | CODE-1(플랫폼 버전 요구)과는 취지 상이 |
| FV-8 | 보안공통기반 | MASVS-RESILIENCE-2 (앱 위·변조 탐지 측면) | 공통기반 자체는 국내 고유 제도 |
| FV-9 | 기타 | MASVS-RESILIENCE-3 (난독화 FV-9.2) | FV-9.1(서비스 특화)은 대응 없음 |

- **MASVS 대응이 없는 국내 고유 항목**: FV-1(명세 일치), 시간및상태·코드오류 유형, FV-8 의 보안공통기반 제도 자체, FV-4.6 의 공동인증서 요구. 이들은 MASVS 를 근거로 축소·생략할 수 없다 (§6).

## 4. 집계

| 겹침 등급 | 컨트롤 수 | 해당 컨트롤 |
|---|---|---|
| 높음 | 9 | STORAGE-1 · CRYPTO-1 · NETWORK-1 · PLATFORM-1 · CODE-3 · CODE-4 · RESILIENCE-2 · RESILIENCE-3 · PRIVACY-1 |
| 중간 | 4 | STORAGE-2 · CRYPTO-2 · AUTH-1 · PRIVACY-4 |
| 낮음 | 2 | AUTH-2 · CODE-1 |
| 없음 | 9 | AUTH-3 · NETWORK-2 · PLATFORM-2 · PLATFORM-3 · CODE-2 · RESILIENCE-1(방향 반대) · RESILIENCE-4 · PRIVACY-2 · PRIVACY-3 |

- "없음" 9개 중 RESILIENCE-1 은 공백이 아니라 **방향 반대**(§5)라는 점에서 성격이 다르다.
- "없음·낮음" 11개 중 SKILL.md §6 이 **확정 공백 6개**(NETWORK-2·PLATFORM-2·PLATFORM-3·AUTH-2·AUTH-3·RESILIENCE-4)와 **재분류 여지 2개**(PRIVACY-2·PRIVACY-3)를 다룬다. CODE-1·CODE-2 는 공백이되 하이브리드 전자정부 앱 점검에서의 실질 효용이 상대적으로 낮아 확정 6개에 포함하지 않았다.

## 5. 방향 반대 항목 — FV-5.1 ↔ MASWE-0051 ⚠️

| 구분 | 📕 FV-5.1 (제도 기준) | 📋 MASWE-0051 (국제 권고) |
|---|---|---|
| 점검 질문 | 앱이 루팅·탈옥을 **유발하는 기능**을 갖고 있는가 (p.27) | 앱이 루팅·탈옥 **탐지를 구현**했는가 |
| 방향 | 플랫폼 보안모델 위배 **금지** — 있으면 부적합 | 방어 기능 구현 **의무** — 없으면 약점 (MAS-R) |
| 구속력 | 전자정부법 체계 검증 기준 | 모범사례 — **구속력 없음** |

- 같은 단어("루팅·탈옥")를 쓰지만 점검 대상이 정반대다. 하나의 발견사항에 두 문서를 근거 구분 없이 병기하면 "탐지 미구현 = FV-5 위반" 또는 "변조 유발 기능 = MASWE 소관" 식의 오판이 발생한다.
- 지적 시 근거 문서를 하나만 선택하고, MASWE-0051 을 쓸 때는 버전(v1.0.0)·조회일(2026-09-17)·"구속력 없음"을 병기한다. 상세 시나리오는 SKILL.md §2.2.

## 6. 원칙 재확인 — "미기재 ≠ 부적합"

- 이 표의 "없음"은 국내 가이드라인의 **결함 목록이 아니다**. `mobile-app-verify` §6 각주의 원칙 그대로 — **미기재 ≠ 부적합**이며, 문서의 침묵이 자동으로 현행 점검 대상·부적합 사유가 되는 것은 아니다.
- 정확한 용어는 "미커버"가 아니라 **"이 가이드라인을 근거로는 지적할 수 없는 영역"** 이다. 해당 영역의 점검은 OWASP 출처·구속력 없음을 병기한 자율 보강 점검으로만 수행한다.
- 역방향도 같다 — OWASP 가 다루지 않는 국내 고유 영역(국산 암호, KISA 신청 절차·서식, 보안공통기반, 공동인증서 등)은 MASVS 를 근거로 평가절하할 수 없다. 제도 판정은 언제나 `mobile-app-verify`·`secure-coding-kr` 원문 기준을 따른다.
