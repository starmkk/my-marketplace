# Save Docs Skill

현재 세션 내용을 검토해 문서로 정리하고 저장한다.
대화 히스토리 전체를 참조할 수 있으므로 직접 내용을 분석한다.

## Step 1: 세션 유형 판별

대화 내용을 보고 다음 기준으로 분류한다:

- **(A) 개발 작업** — 코드 작성·수정, 기능 구현, 버그 수정, 설정 변경 등 실질적 변경이 있었던 세션
- **(B) 질문·리뷰** — 개념 설명, 코드 리뷰, 조사·탐색, 의사결정 논의 등 변경 없이 정보 교환 위주인 세션

## Step 2: 사용자 확인

`AskUserQuestion`으로 다음을 확인한다:
- **토픽명**: 파일명에 사용할 짧은 영문 또는 한글 키워드 (예: `github-commit-skill`, `mnn-build-fix`)
- **문서 유형**: 판별한 세션 유형을 제안하되 사용자가 변경 가능하도록 옵션 제공

## Step 3: 저장 경로 결정

다음 순서로 저장 경로를 결정한다:

```bash
DOCS_DIR="${CLAUDE_DOCS_DIR:-$HOME/Documents/claude/docs}"
mkdir -p "$DOCS_DIR"
```

- `$CLAUDE_DOCS_DIR`가 설정된 경우 해당 경로 사용
- 미설정 시 `~/Documents/claude/docs/` 사용 (macOS·Linux 공통)

> 다른 PC에서 경로를 바꾸려면 셸 프로파일에 `export CLAUDE_DOCS_DIR=/원하는/경로` 를 추가하면 된다.

## Step 4: 문서 작성

### 파일명 규칙

두 유형 모두 단일 파일로 저장한다:

```
YYYYMMDD_<topic>.md
```

날짜는 오늘 날짜 기준.

### 문서 구조

**개발 작업**:
```markdown
# <topic>

**날짜**: YYYY-MM-DD
**유형**: 개발 작업

## 요약
이 세션에서 무엇을 했는지 2-3문장으로.

## 개발 계획
세션 초반에 수립한 접근 방식, 설계 방향, 단계별 계획.

## 구현 결과

### 주요 결정 사항
- 왜 이 접근법을 선택했는지 등 중요한 기술적/설계적 결정

### 코드/파일 변경 내역
- `경로/파일명` — 변경 내용 한 줄 요약

## 다음 할 일
- [ ] 후속 작업 항목

## 핵심 키워드 요약

| 키워드 | 내용 |
|--------|------|
| 주요 기술/도구 | |
| 해결한 문제 | |
| 적용한 패턴/방식 | |
| 참고 링크 | |
```

**질문·리뷰**:
```markdown
# <topic>

**날짜**: YYYY-MM-DD
**유형**: 질문·리뷰

## 요약
이 세션에서 다룬 내용 2-3문장으로.

## 주요 내용
핵심 정보, 결론, 권고사항 등.

## 참고 사항
추가로 기억할 맥락이나 링크.

## 핵심 키워드 요약

| 키워드 | 내용 |
|--------|------|
| 주요 개념 | |
| 결론/권고 | |
| 참고 링크 | |
```

## Step 5: 저장 완료 보고

저장된 파일 전체 경로를 사용자에게 알린다.
