# 한국어 CER/WER 계산 주의사항

## 1. CER vs WER

| 메트릭 | 단위 | 한국어 적합도 |
|---|---|---|
| **CER (Character Error Rate)** | 글자 단위 | ✅ 한국어에 권장 |
| **WER (Word Error Rate)** | 어절 단위 | △ 띄어쓰기에 민감 |
| **PER (Phoneme Error Rate)** | 음소 단위 | ✅✅ 가장 정확하지만 자모 분해 필요 |

본 스킬은 **CER을 기본 메트릭**으로 사용. 이유:
- 한국어는 띄어쓰기가 모호 ("좋은아침" vs "좋은 아침" 모두 OK)
- 어절 단위 WER는 띄어쓰기 차이로 폭증
- 글자 단위 CER이 ASR 평가의 한국어 표준

WER는 영어처럼 띄어쓰기가 명확한 언어용.

## 2. CER 계산 식

```
CER = (S + D + I) / N
  S = 치환된 글자 수
  D = 삭제된 글자 수
  I = 삽입된 글자 수
  N = 정답 텍스트의 총 글자 수
```

`jiwer` 패키지가 Levenshtein distance 기반으로 자동 계산.

## 3. 한국어 텍스트 정규화

ASR 결과와 정답 텍스트 간 사소한 차이가 CER을 오염시키므로 정규화 필수.

본 스킬의 `_asr.py`의 `normalize_korean()`:
1. 소문자화
2. Zero-width 문자(ZWSP, ZWNJ, BOM) 제거
3. 구두점/특수문자 제거 (`,.!?…` 등)
4. 공백 압축

### 정규화로 처리되는 케이스
| 원본 | ASR 출력 | 정규화 후 비교 |
|---|---|---|
| "오케이 케이티" | "오케이 케이티." | "오케이 케이티" == "오케이 케이티" ✅ |
| "Hi, KT" | "hi kt" | "hi kt" == "hi kt" ✅ |
| "안녕하세요" | "안녕하세요!!" | "안녕하세요" == "안녕하세요" ✅ |

### 정규화로 처리 못 하는 케이스
| 원본 | ASR 출력 | 비고 |
|---|---|---|
| "API" | "에이피아이" | 외래어 한글 표기 차이 |
| "123" | "백이십삼" / "일이삼" | 숫자 표기 차이 |
| "Wi-Fi" | "와이파이" / "위파이" | 외래어 |
| "1번" | "일번" / "한 번" | 숫자+조사 |

이런 경우는:
- **합성 단계에서 정답 텍스트를 ASR 친화적으로 표기** ("API" → "에이피아이"로 미리 정규화)
- 또는 keyword_map의 alias 시스템으로 대응

## 4. KWS 키워드의 짧음에 따른 CER 민감도

KWS 키워드는 보통 4~8글자. CER 임계값별 의미:

| CER | 4글자 키워드 | 8글자 키워드 |
|---|---|---|
| 0.10 | 0.4글자 (실질 0~1글자) | 0.8글자 (실질 0~1글자) |
| 0.20 | 0.8글자 (실질 1글자) | 1.6글자 (실질 1~2글자) |
| 0.30 | 1.2글자 (실질 1~2글자) | 2.4글자 (실질 2~3글자) |

짧은 키워드일수록 한 글자 차이가 CER에 크게 작용한다는 뜻.
키워드가 짧으면 임계값을 약간 더 엄격하게(0.20) 잡는 게 좋다.

## 5. 자모 분해 PER (선택적 확장)

CER로 부족할 때 자모 단위 PER 계산:

```python
import jamo  # pip install jamo

def to_jamo_seq(s: str) -> str:
    """한국어 문자열 → 자모 시퀀스"""
    return "".join(jamo.h2j(s))

ref_jamo = to_jamo_seq(ref)  # "오케이" → "ㅇㅗㅋㅔㅇㅣ"
hyp_jamo = to_jamo_seq(hyp)
per = jiwer.cer(ref_jamo, hyp_jamo)
```

자모 PER은 CER보다 1.5~2배 작은 값을 보인다 (글자당 자모가 2~3개라).
받침/이중모음 정확도까지 보고 싶을 때 유용.
본 스킬의 기본은 CER이지만, 필요 시 `_asr.py`에 PER 헬퍼 추가 가능.

## 6. jiwer 사용 팁

### 정상 호출
```python
from jiwer import cer, wer
score = cer(reference, hypothesis)  # 0.0 ~ 1.0+
```

### 빈 문자열 처리
```python
cer("", "")          # 0.0 (정상)
cer("", "안녕")       # 무한대 또는 예외 가능
cer("안녕", "")       # 1.0 (모두 삭제)
```

본 스킬의 `_safe_metric()`이 가드해줌.

### 1.0 초과 가능
ASR이 hallucination으로 정답보다 훨씬 긴 텍스트를 출력하면 CER이 1.0을 초과한다.
이 경우 `min(cer, 1.0)`으로 클립하거나, 그대로 두고 임계값 0.30 등으로 자동 폐기.

## 7. 다중 정답 비교 (선택)

키워드의 여러 valid 표기를 모두 정답으로 인정:

```python
candidates = ["오케이 케이티", "오케이케이티", "ok kt"]
best_cer = min(cer(c, hyp) for c in candidates)
```

본 스킬은 단일 정답만 지원. 다중 정답이 필요하면 `keyword_map.json`을
{keyword: [aliases]} 형태로 확장하면 됨 (후속 작업 후보).

## 8. 결과 해석 팁

### 8.1 평균 CER만 보지 말 것
평균이 0.20이어도 분포가 bi-modal일 수 있음:
- 70%는 CER<0.05 (완벽)
- 30%는 CER>0.50 (망함)
- 평균은 0.18

이 경우 70%만 살리면 OK. 평균보다 **분포 히스토그램**을 보자.
본 스킬의 `qa_report.csv`를 pandas로 읽어 시각화 권장.

### 8.2 화자별 / 키워드별 grouping
QA report를 speaker_id, text로 group by 해서 평균 CER 보면 패턴이 보인다:
- 특정 화자만 CER 높음 → 그 화자 풀에서 제외
- 특정 키워드만 CER 높음 → 키워드 변경 또는 정규화 보강
